# Масштаб quad-режима: меньше бордюра

Анализ (2026-11-12). Реализован вариант B (2026-11-13): `video_out.v` рисует строку вперёд в буфер `video_px.v`,
показ на `clk_sys` / 4, OSD с `ce` (`kg_osd_overlay` `CE_IN`); подробности — [ARCHITECTURE.md](ARCHITECTURE.md),
раздел «Quad-режим». Вопрос: в quad-режиме бордюр визуально слишком широкий, можно ли
взять меньшее разрешение экрана.

## Что сейчас

Растр VGA один для обоих режимов: 896 × 640 тактов `clk_bus` (28,03 МГц), 31,25 кГц, 48,8 Гц, видимая часть
768 × 608 (`zx_timing.v`, `video_out.v`). Квадрант 384 × 304 — вся видимая картинка Pentagon в масштабе 1:1:
бордюр 64 + 64 пикселя по горизонтали, 64 + 48 строк по вертикали.

| | Квадрант | Paper по ширине | Paper по высоте | Paper по площади |
|---|---|---|---|---|
| Сейчас | 384 × 304 | 67 % | 63 % | 42 % |

Между двумя paper получается 128 пикселей бордюра по горизонтали и 112 строк по вертикали.

## Почему не поможет просто «меньшее разрешение»

Аналоговый VGA не передаёт число пикселей: монитор растягивает на экран видимую часть строки по времени и
видимые строки по числу строк режима. Доля бордюра меняется только двумя способами:

- показывать меньше бордюра (обрезка);
- делать пиксель длиннее (ниже частота пикселей) и повторять строки.

Если просто обрезать бордюр в том же растре, paper останется того же размера, вокруг появится чёрное поле.

## Варианты

### A. Только обрезка (например, до 32 пикселей)

Несколько строк в `video_out.v`. Paper того же размера, вокруг чёрное поле. Это косметика, задачу не решает.

### B. Масштаб 4/3 в том же растре (рекомендуется)

- Частота пикселей в quad-режиме 21,02 МГц = `clk_sys` / 4: разрешение от `clk_sys`, новый выход PLL не нужен
  (VCO 925 МГц / 44).
- Строка остаётся 896 тактов `clk_bus` = 2688 тактов `clk_sys` = ровно 672 пикселя по 21 МГц. Фаза пикселя
  относительно строки постоянна, дрожания нет.
- hsync, vsync и 640 строк не меняются: для монитора это тот же режим, Win+`~ переключает без
  пересинхронизации.
- По горизонтали: 768 тактов видимой части = 576 пикселей, квадрант 288 = 16 + 256 + 16. Все пиксели одной
  ширины.
- По вертикали: 304 строки VGA на квадрант = 228 строк Спектрума = 18 + 192 + 18. Строка `src = sy * 3 / 4`,
  каждая третья строка показывается дважды. Знакоместа будут высотой 11 / 11 / 10 строк VGA. Монитор и так
  масштабирует 640 строк на свою матрицу нецелым коэффициентом, поэтому это должно быть мало заметно.
- Пропорции пикселя остаются прежними (4/3 по обеим осям).

| | Квадрант (пиксели Спектрума) | Paper по ширине | Paper по высоте | Paper по площади |
|---|---|---|---|---|
| B (4/3) | 288 × 228 | 89 % | 84 % | 75 % |

Что менять:

1. **Выход видео.** Последнюю ступень (RGB, синхроимпульсы, `V_CLK`) перевести на `clk_sys` с разрешением:
   ce28 в полноэкранном режиме, ce21 в quad. `V_CLK` уже делается импульсом из `clk_sys` (`bus_ce.v`), DAC
   изменение частоты не заметит.
2. **Чтение квадрантов.** `q_go` выдавать только при смене `src`, буфер выбирать по `src[0]`, `q_brd_addr`
   считать от `src`. Обращений к SDRAM станет меньше (228 строк вместо 304 на квадрант). Строчный буфер
   `pentagon.v` не меняется.
3. **OSD — главная сложность.** `kg_osd_overlay` работает на `clk_bus` без разрешения. Если пропустить через
   него картинку 21 МГц, она пересэмплируется на 28 МГц, и пиксели снова станут неравной ширины. Нужен вход
   `ce` у `kg_osd_overlay` (по умолчанию «всегда 1»). Это совместимое изменение общего модуля `modules/`
   (свои правила и тесты, `modules/CLAUDE.md`). Смещение OSD в quad-режиме задаётся уже существующими входами
   `h_offset` / `v_offset` (`H_OFFSET_IN`, `V_OFFSET_IN`). При 21 МГц OSD станет в 4/3 шире, но в 576 пикселей
   укладывается.
4. **Ресурсы.** Слайсы заняты на 94 % ([OPTIMIZATION.md](OPTIMIZATION.md)). Логика небольшая (счётчики, мультиплексор
   разрешений), но её лучше делать после оптимизации размера.

С чего начать: с `ce` в `kg_osd_overlay`, без него остальное не даст ровных пикселей.

### C. Масштаб 4/3 на 28 МГц, без новой частоты

Каждые 3 пикселя растягиваются на 4 такта шириной 1, 1 и 2. Правится только `video_out.v`, OSD не трогается.
Но на дизеринге и тексте неравная ширина пикселей хорошо видна. Годится как быстрый прототип, чтобы оценить
размер на плате.

### D. Отдельный VGA-режим для quad (640 × 480 при 60 Гц, квадрант 320 × 240, всё 1:1)

Самая чистая картинка, но:

- монитор заново ловит сигнал (1–2 с чёрного экрана) при каждом Win+`~;
- 60 Гц против 48,8 Гц Спектрума — рывки при прокрутке;
- нужен отдельный растр и свой тактовый домен для компоновщика.

Не рекомендуется.

### Другие масштабы

Из VCO 925 МГц целое число тактов в строке дают ещё 22,02 МГц (VCO / 42, масштаб 14/11, бордюр около 22
пикселей, 704 такта в строке). Но нужен отдельный выход PLL и BUFG, а повтор строк 11 → 14 неровный. Частоты
VCO / 36, / 37, / 39, / 40 дают нецелое число тактов в строке: фаза пикселя гуляет от строки к строке.

## Полноэкранный режим

Удвоитель показывает весь растр Pentagon с тем же соотношением бордюра и paper. Его можно оставить как есть.
Обрезка до 32 пикселей там требует нецелого масштаба, это отдельный вопрос.
