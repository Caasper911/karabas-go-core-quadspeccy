## Тайминг

Запас по `clk_bus` +0,026 нс, но T80 тут ни при чём. Критические пути идут из регистров ответа SDRAM (`sdram/aqN`, `bqN`,
домен `clk_sys`) в машины (`qbuf`, `nz`, регистры данных CPU) — это переход `clk_sys` → `clk_bus`, на который отведён
один период `clk_sys` (11,9 нс). Из них 11 нс — разводка через весь кристалл: четыре машины разнесены по нему.
При заполнении 94 % такие пути будут ломаться от любого изменения, поэтому этап 0 обязателен первым.

## Этапы

### 0. Тайминг: развести переходы между доменами (сначала)

- **0.1** Ответы SDRAM переложить в домен `clk_bus` внутри `sdram_ctrl`: `q` и `ack` каждого канала — в регистры на
  `clk_bus` (с разрешением по фронту `clk_bus`, как `bus_ce`), рядом с контроллером. До машин тогда идёт путь на
  целый период `clk_bus` (35,7 нс), короткий путь между доменами остаётся внутри контроллера. +≈ 80 FF, LUT почти не
  меняются; чтение CPU +1 такт `clk_bus` (= 3 `clk_sys`): бюджет 42 → 45 из 48, проверить в симуляции (`late`).
- **0.2** Запросы машин (`req`, адрес, данные) — так же: регистр в `clk_bus` у контроллера, без логики перед ним.
- Ожидаемо: запас `clk_bus` — единицы наносекунд; дальше можно включать оптимизацию по площади.
- Сделано (2026-11-12): обе ступени в `sdram_ctrl` (вход `clk_bus`). Чтобы не съесть весь бюджет чтения, машина
  отдаёт запрос прямо в T1, а запись подтверждается на ACT. Запас чтения в симуляции: до этапа 4 такта `clk_bus`
  в худшем случае, после — 3 (128 ROM) и 1 (LDIR при совпадении с регенерацией).

### 1. Настройки синтеза и map (дёшево)

- **1.1** `map -lc area` (объединение LUT: две функции LUT5 в одном LUT6). Обычно −5…10 % слайсов.
- **1.2** XST `-opt_mode Area` (сейчас Speed) — после этапа 0, проверяя тайминг.
- **1.3** Подобрать `MAP_T` (seed размещения) — при заполнении > 90 % влияет на тайминг заметно.
- Ожидаемо: 94 % → ≈ 85–88 % слайсов.

### 2. Память из LUT в блочную память

- **2.1** `brd_mem` (512 × 3, цвет бордюра строк) и `qbuf` (64 × 16, строка quad-режима) каждой машины → RAMB8
  (чтение синхронное: +1 такт в конвейере `video_out`). −≈ 80 LUTRAM и мультиплексоры чтения на машину, ≈ −400 LUT.
- **2.2** `kg_osd_overlay` и `ld_fifo` уже в BRAM / мелкие — не трогать.

### 3. Эмуляция SD

- **3.1** Байтовый интерфейс вместо SPI-слейва для образа: в режиме Image порт `#EB` обменивается байтом с
  `kg_sd_emu` напрямую (как `nextor_sd` MSX), без последовательной передачи на 7 МГц. ≈ −50 LUT на машину и
  быстрее обмен; SPI-мастер остаётся только для реальной карты (он один — у её владельца).
- **3.2** Один автомат карты на четыре машины с разделением по времени: состояние каждой карты (state, cmd, arg,
  счётчики, LBA) — в LUTRAM / BRAM, логика одна, машины обслуживаются по очереди (каждой нужен байт раз в
  ≥ 4 T = 32 такта). ≈ −600…800 LUT. Сложно, нужен свой тест на 4 карты.

### 4. Процессор — главный объём (64 % LUT)

- **4.1** Замерить отдельной сборкой на XC6SLX25 другие ядра Z80 (tv80, NextZ80 и т.п.) с теми же требованиями:
  точные T-состояния (Pentagon, мультиколор), недокументированные флаги, `WAIT`. Брать, только если выигрыш
  > 20 % и проходят тесты (ZEXALL, тайминг-тесты).
- **4.2** Один Z80 на четыре машины («барабанный» процессор): четыре контекста по очереди на 14 МГц, состояние
  контекстов в памяти. ≈ −5000 LUT — место под AY и TR-DOS для всех. Это новое ядро процессора (T80 так не
  разделить: его состояние — сотни триггеров по всему коду): большой отдельный проект, только если без него не
  уложить нужные функции.

- Сделано: tv80 вместо T80 (отдельный синтез: T80 2270 / tv80 1325 / Z80 dr.Titus 1106 / A-Z80 1774 LUT; Titus
  без разрешения такта и на обоих фронтах, alpha — не взят). В проекте −1160 LUT (по 290 на машину), 95 → 90 %
  слайсов. Вариант дальше — один tv80 на четыре машины (4.2): общая логика, четыре комплекта состояния,
  разнесённые CEN; проверка — 4 × tv80 против четырёхконтекстного ядра такт в такт. ≈ −4000 LUT.

- Сделано: один tv80 на четыре машины (4.2) — `tv80_quad` / `tv80q_core` (генерируется `tools/mkquad.py`),
  слоты 2k / 2k+1. 9980 → 6133 LUT, 90 → 58 % слайсов, запас clk_bus 8 нс. Проверено на плате.

### 5. Будущие функции — сразу экономно

- **AY**: не четыре отдельных YM2149 (≈ 400 LUT каждый), а один генератор с разделением по времени: регистры
  четырёх AY в LUTRAM, тон / шум / огибающая считаются по очереди (они медленные: 1,75 МГц / 16). ≈ 500 LUT на
  все четыре.
- **TR-DOS / FDC**: один контроллер на образах через `img_sdc`, переключаемый между машинами, или только у одной.
